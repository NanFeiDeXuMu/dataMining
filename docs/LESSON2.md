# 第二课实操：从行程事务中发现关联模式

目标：把每条行程转换成一组类别项，使用 Apriori 与 FP-Growth 发现频繁项集和关联规则，并用支持度、置信度和提升度评价规则。

## 练习一：理解事务表示

打开“模式发现”，选择一条匹配行程，检查它的 8 个类别项：日期类型、上车时段、上下车行政区、距离区间、费用区间、支付方式和乘客数区间。

- 为什么区域 ID 不直接作为关联项？
- 连续距离为什么需要分箱？
- 改变分箱边界可能怎样改变规则？

## 练习二：手算一条规则

选择规则 `A → B`，记录总事务数、包含 A 的事务数、包含 B 的事务数和同时包含 A、B 的事务数，然后计算：

```text
support    = count(A ∪ B) / N
confidence = count(A ∪ B) / count(A)
lift       = confidence / support(B)
```

将手算结果与页面结果比较。

## 练习三：改变阈值

分别提高最小支持度、置信度和提升度，记录规则数量及排名变化。解释为什么高置信度规则仍可能只是后件本身非常常见。

## 练习四：比较算法

阅读 `urbanpulse/patterns.py`：Apriori 枚举候选项集，FP-Growth 压缩公共前缀。确认报告中的 `identical=true`，说明两种算法在同一事务、阈值和最大项集长度下得到相同频繁项集。

## 练习五：谨慎解释

选择一条高提升度规则，写出：

> 在【数据月份、默认清洗与固定分箱】下，前件和后件共同出现于【N 条、支持度】行程；出现前件时后件比例为【置信度】，相对后件基准比例为【提升度】倍。该规则描述关联，不证明【因果关系】，还需检查【区域、时段或数据记录机制】。
