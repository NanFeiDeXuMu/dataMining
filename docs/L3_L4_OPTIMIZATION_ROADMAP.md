## 3. 阶段一：v0.3.1 规则评价与证据，已完成

完成记录：完整方向规则 5,182 条，默认展示匹配 887 条、751 组 A/B 关系；真实快照 `run-2496d677`。测试与依赖检查结果统一记录在 [当前状态](../CURRENT_STATUS.md)，练习见 [第二课](LESSON2.md)。

**要回答：这条规则为什么值得看，它的分母、双向关系和限制是什么？**

### 已交付内容

1. 共用计数评价函数，提供双向置信度、Kulc、IR、Jaccard、cosine 和 lift。
2. 页面从完整事务表独立复算 2×2 列联表，核对前后件计数、总分母与保存计数，并提供 `record_id` 行程示例。
3. 构建保存已挖掘项集范围内的全部方向规则；展示阈值由查询层应用。移除旧生成阶段预过滤和默认 200 条查询截断。
4. 查询阈值、最大长度和分母读取所选快照元数据；保留旧快照只读兼容，并明确其预过滤边界。
5. 同一 A/B 组合折叠展示，支持 support/lift/Kulc 排序与分页；CSV 包含全部匹配方向及快照、筛选范围。

### 指标合同

令 `N` 为该数据范围内事务数，`nA`、`nB` 为包含前件/后件的事务数，`nAB` 为同时包含二者的事务数：

```text
n11 = nAB
n10 = nA - nAB
n01 = nB - nAB
n00 = N - nA - nB + nAB
support = nAB / N
confidence(A→B) = nAB / nA
confidence(B→A) = nAB / nB
lift = N * nAB / (nA * nB)
Kulc = (nAB / nA + nAB / nB) / 2
IR = abs(nA - nB) / (nA + nB - nAB)
```

零分母返回不可计算状态并说明原因。增加不含 A/B 的事务时，Kulc、IR 应不变，support 和 lift 通常改变。χ² 可用作后续教学项；若引入显著性判断，需另行处理小期望频数、多重比较与时空依赖，不能以百万记录带来的小 p 值充当实际价值。

### 实现与验收依据

- 计数定义和规则生成位于 `urbanpulse/patterns.py`，查询与独立证据位于 `urbanpulse/analytics.py`，分页与导出位于 `app.py`。
- 课件 L3 p.38 的“高置信度但 lift < 1”案例可准确复算；空事务增量测试、交换 A/B 对称性测试、零分母测试通过。
- 真实规则的四格计数可与独立 SQL 核对，和为 N，均非负；样例与规则使用相同数据范围。
- 旧快照只读兼容及“快照配置与全局配置不同”的测试通过。
- 新产物仍通过 Apriori/FP-Growth 等值检查；默认清洗行程数不因新增评价指标而改变。

## 4. 阶段二：v0.3.2 约束与地理分层，P1，3–4 天

**要回答：指定日期/地区内有哪些模式；同一模式在行政区与具体区域层面有什么差异？**

### 先做好约束语义

| 用户动作 | 执行方式 | 分母 |
|---|---|---|
| “规则必须包含工作日” | 从全月规则筛选，或采用保持全月计数的等价挖掘优化 | 全月 N |
| “只挖工作日行程” | SQL 过滤事务，再聚合篮子并重新挖掘 | 工作日子集 N |
| “只看距离、费用、支付” | 投影事务项；不删除由投影产生的空事务对 N 的贡献 | 原数据范围 N |
| “后件必须是距离项” | 规则生成/筛选阶段约束，支持计数仍来自完整数据范围 | 原数据范围 N |

先支持日期、上下车行政区、可用维度、前后件维度、最大长度及最低计数。数据约束用参数化 SQL；对已证明安全的约束再做搜索剪枝。

- support 下限、长度上限、同一互斥字段不能同时取两个值，可用于反单调剪枝。
- “必须包含某项”不能因当前前缀暂未包含该项就剪掉所有扩展；可使用锚点投影，但必须保留原范围 N，并另外取得前后件的原范围边际计数。
- 置信度、lift、Kulc、平均值约束不能直接套用普通频繁项集的反单调剪枝。
- 现有 `_transactions()` 会跳过空篮子；后续维度投影/去项时应独立携带分母，避免静默改变支持度。

### 再增加两级地理表示

以现有 `zones` 映射建立上车/下车各自的 `行政区 → taxi zone` 层级，先提供“行政区模式”和“区域模式”两套清晰口径。展示祖先规则与细粒度规则的差异；地理映射产生的 `具体区域 → 所属行政区` 是定义关系，应标记或隐藏。

行政区沿用 1% 作为基线；区域层试验可比较 0.1%、0.5%、1%，同时设置显式最低计数，例如 100 条。以上是待比较的配置，不是已验证最优阈值，也不保证统计可靠性。混合层级阈值须定义项集适用规则后才开放。

更高的父层阈值不能用于剪掉可能达到较低子层阈值的模式。首版可分层独立挖掘，避免错误继承阈值；后续共享候选需按最低适用门槛保留候选。祖先冗余按共同计数的预期比例和置信度差异标记，阈值记录入配置，保留可展开原始证据。

### 产物与验收

- 将现有硬编码分箱抽成版本化配置；第一版保持现有边界，变化时记录 `binning_version` 和 `hierarchy_version`。
- 增加可选模式实验入口，复用清洗快照，不为每次改阈值重复训练预测模型。新增 `run-*` 记录父快照、SQL 范围、配置、N、源文件哈希和完整性状态；子集实验由页面独立选择。
- `active.json` 继续只指向通过全套合同验证的完整快照；仅有模式产物的实验不得替代主快照。旧快照与原始输入保持不可变。
- 同一配置下，“完整挖掘后筛选”与“安全约束下推”逐项、逐计数相同；空子集、空投影、互斥字段和锚点计数均有反例测试。
- 增加“父层未过高阈值、子层通过低阈值”测试，防止漏挖；抽查区域映射与祖先计数守恒。
- UI 明确显示当前分母、数据范围及是否重新挖掘；证据查询复用同一范围。超时或资源上限触发后标记实验未完成，不激活、不发布为完整结果。

## 5. 阶段三：v0.3.3 结果压缩与可复现实验，P1，2–3 天

**要回答：哪些模式重复，参数如何影响结果，优化是否真的有效？**

### 压缩展示

- 提供全项集、闭合项集、最大项集三种视图，对照 L3 p.13–14 解释：完整闭合表示可保留支持信息，最大项集不能恢复所有子集的精确支持度。规则计算继续依赖完整支持计数。
- 当前只挖长度 ≤ 3，不能仅因没有保存超集就宣称“全局闭合/最大”。首版明确标记“在长度 ≤ 3 的搜索范围内闭合/最大”。若要判断已保存项集在全部长度下的闭合性/最大性，需要额外核查所有可能的单项扩展；这仍不等于枚举了全部长度的闭合/最大项集。
- 保留完整原始结果，压缩只增加选择视图；报告压缩前后数量和支持计数可恢复范围，不能预设一定能大幅压缩。

### 实验优先于性能改写

1. 固定数据哈希、分箱、硬件/线程、版本与规则口径，比较 support `{1%, 2%, 5%}`、最大长度 `{2, 3, 4}`；低支持度区域实验单列，先限制范围并设置资源上限。
2. 每个配置预热后至少重复 5 次，记录中位时间、离散程度、候选数/各层频繁数、FP 树节点数，以及注明测量口径的内存指标。事务构建、挖掘、规则生成分别计时；输出计数必须一致。
3. 若候选生成确为瓶颈，将 Apriori 的全集组合枚举改成同前缀连接再剪枝（L3 p.22–23）；若递归建树显著，再添加 FP 单路径优化（p.32–34）。不承诺预定倍数加速。
4. ECLAT（p.27）作为可选算法实验：对压缩篮子建立 ID 交集，支持度是交集篮子的**权重和**，不是交集基数；与现有两算法及小规模穷举计数核对。
5. 增加周粒度稳定性报告：对固定候选计算各周支持度、双向置信度、Kulc 和计数。单月已被全量探索，结果仅称回溯稳定性；若要独立验证，先冻结候选、分箱和阈值，再评价未用于选择的新月份。跨月时间特征须先遵循 DECISIONS 的时区策略要求。

### 验收

- 构造长度 4 的反例，证明长度截断不会被误标为全局闭合/最大；在完整小样本上验证闭合支持信息恢复，以及最大项集的信息损失。
- 对优化算法，使用小规模穷举作为独立计数参照，辅以原有加权/展开等价和确定性随机测试。
- 交付真实敏感性表、性能表及 3 条案例卡；每条卡包含范围、分母、计数、指标、周度变化和解释边界。不要求一定发现“强”“稳定”模式，无结果也如实记录。
- 如果基准没有显示性能收益，保留简单实现，把课程交付重点放在可解释性与实验结论。

## 6. 后续拓展的进入条件

### 低频与负模式：阶段二后可选，预计另需 1–2 天

对照 L4 p.5、p.7–9，单独生成跨字段的候选对，对边际计数设置门槛，再直接计算共同计数（包括 0）、Kulc、IR 和列联表。现有快照虽保存全部方向，仍只覆盖联合支持度 ≥ 1% 的项集；低共现及零共现候选不能靠降低页面 lift 阈值恢复。

排除同一字段不同取值造成的结构性互斥，单独标记层级定义关系；小 Kulc 表示低双向重合，不自动证明替代关系或原因。给出跨周重算、同字段互斥和零共同计数的测试。课程中的 epsilon 是探索阈值，应在配置中说明严格小于还是小于等于。

### GSP 序列：阶段一、二完成后可选，预计另需 3–5 天

现有源字段没有稳定乘客或车辆标识；`VendorID` 是供应商类别，`record_id` 是文件行号，均不能连接成个人/车辆连续轨迹。

可复用 `zone_hour`，定义一条 SID 为一个 `区域 × 日期`，元素为按小时排序的低/中/高记录量状态（必要时加时段标签）。阈值只用发现期确定；测试期不重新拟合分箱。先限制模式长度 ≤ 3，以朴素子序列匹配作参照，再实现课件的 GSP。

支持度分母是纳入的有效 SID 数；同一 SID 多次匹配只计一次。写明区域纳入规则、零记录/缺数据处理、是否允许跳时以及间隔约束。首版使用普通有序子序列；若要求相邻小时或最大间隔，应单独论证剪枝规则，不能直接沿用所有子序列的剪枝。验收覆盖重复匹配、顺序颠倒、同元素共现与跨元素先后之别。

这些模式描述区域记录量的先后变化。后续用于预测或异常检测前，仍需独立评价其增益。

### 子图：暂缓，待 OD 图问题明确后再估算

对照 L4 p.35–44，可按天或固定时段构建一组有向 OD 图，支持度定义为包含目标结构的图数除以有效图总数。先明确节点标签、边门槛、方向、图匹配语义，再考虑 gSpan/CloseGraph。OD 热度图或热门边排名本身不等于频繁子图挖掘。

目前引入图挖掘的成本高于改善现有模式解释。若课程要求演示，可先做极小图集的精确枚举实验，不把完整 gSpan 纳入最近一次发布。
