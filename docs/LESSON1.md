# 第一课实操：数据如何变成可信结论

目标：用 UrbanPulse 完成一次“提出问题 → 理解数据 → 决定清洗 → 汇总 → 评价”的小型分析。

## 练习一：先理解字段

打开“字段字典”，解释 `PULocationID`、`trip_distance` 和 `total_amount`：

- 一条记录代表什么？这三列分别是什么属性类型？
- 距离的单位是什么？总额与计价费用有什么区别？
- 为什么区域 ID 不能取均值或直接计算欧氏距离？
- 为什么不能用 `tip_amount` 比较现金支付与信用卡支付的全部小费？

## 练习二：清洗是一个可解释的选择

从默认规则开始，每次只增加一个待核查规则，记录结果：

| 实验 | 窗口原始数 | 保留数 | 保留率 | 总额均值 | 总额中位数 |
|---|---:|---:|---:|---:|---:|
| 默认规则 | | | | | |
| 默认 + 排除零距离 | | | | | |
| 默认 + 排除负费用 | | | | | |
| 默认 + 排除总额超过 300 美元 | | | | | |

选择一条被标记的原始记录，写出可能的合理解释和需要补充的证据。不要直接将它标注为欺诈。

## 练习三：公平地比较

1. 比较工作日与周末的日均小时订单量。
2. 解释“总量”与“日均量”的区别，核对日历天数分母。
3. 筛选一个区域，观察其模式是否与全市一致。
4. 比较清洗前后的日趋势与区域排名。
5. 检查费用直方图范围外的记录，说明为什么不应只凭可见柱形得出结论。

## 练习四：让其他人复核你的结论

导出当前窗口 JSON 报告，并按下面的模板写三条发现：

> 在【月份 / 日期 / 上车区域】中，使用【清洗规则】，基于【N 条记录 / N 个日历日】，观察到【描述性事实与数值】。该结论不能证明【因果或泛化限制】，还需检查【可能的混杂或数据质量问题】。

## 练习五：验证可复现性

重新执行 `python -m urbanpulse build --month 2025-01`，比较两次报告和产物：

- 原始文件 SHA-256 不变。
- 清洗规则与保留记录数一致。
- `sum(zone_hour.trip_count)` 等于 `cleaned_trips` 的行数。
- 未观测到行程的区域-小时保留为 0，费用统计保留为空，不填成 0 美元。

## 本阶段交付

- 一份字段理解笔记。
- 一张清洗策略对比表。
- 三条带范围、分母和局限的发现。
- 一份导出的分析报告。

此时不需要训练模型。下一课可以将时段、区域、距离区间等离散化，基于同一批行程练习关联规则。
