# 第二课实操：从行程事务中发现关联模式

目标：把每条行程转换成一组类别项，使用 Apriori 与 FP-Growth 发现频繁项集和关联规则，并用完整计数、双向置信度、提升度、Kulc 和 IR 评价规则。对应课件 L3 p.37–47；v0.3.1 已实现评价与证据。

## 练习一：理解事务表示

打开“模式发现”，选择一条匹配行程，检查它的 8 个类别项：日期类型、上车时段、上下车行政区、距离区间、费用区间、支付方式和乘客数区间。

- 为什么区域 ID 不直接作为关联项？
- 连续距离为什么需要分箱？
- 改变分箱边界可能怎样改变规则？

## 练习二：手算一条规则

在“模式发现”选择一组 A/B 关系，展开“双向规则与计数证据”。记录总事务数 N、包含 A 的事务数 nA、包含 B 的事务数 nB 和同时包含二者的事务数 nAB。A 和 B 可以各包含多个属性项，然后计算：

```text
n11 = nAB; n10 = nA - nAB; n01 = nB - nAB; n00 = N - nA - nB + nAB
support = nAB / N
confidence(A→B) = nAB / nA
confidence(B→A) = nAB / nB
lift = confidence(A→B) / (nB / N)
Kulc = (confidence(A→B) + confidence(B→A)) / 2
IR = abs(nA - nB) / (nA + nB - nAB)
```

四格计数之和必须等于 N，且均非负。页面会从完整事务表独立重算这些计数，并与保存规则核对。将手算结果与页面比较；零分母应显示不可计算，不能填 0。前 100 条证据只是按行号排序的共同出现示例，不是计算分母或随机样本。

## 练习三：改变阈值

分别改变最小支持度、置信度和提升度，记录“匹配方向规则数”和“折叠后的属性组数”；按支持度、lift、Kulc 分别排序，比较排名。A→B 与 B→A 共享 lift、Kulc、IR，但置信度通常不同；某个方向未通过阈值时，它仍可在证据卡中用于比较。

新快照保存支持度 ≥ 1%、项集长度 ≤ 3 范围内的全部方向规则；置信度 0.35、lift 1.05 是展示默认值，可以调低。旧快照已在构建时过滤，只能在保存边界内浏览，需重建才得到完整覆盖。降低 lift 不等于实现负模式挖掘，低于联合支持度门槛的项集仍然缺失。

“规则必须包含工作日”只是筛选含这个项的规则，分母仍是全月；它不是只对工作日行程重新挖掘。CSV 导出全部匹配方向及快照/筛选口径，不受当前页数量限制。

## 练习四：比较算法

阅读 `urbanpulse/patterns.py`：Apriori 枚举候选项集，FP-Growth 压缩公共前缀。确认报告中的 `identical=true`，说明两种算法在同一事务、阈值和最大项集长度下得到相同频繁项集。

## 练习五：谨慎解释

选择一条高提升度规则，写出：

> 在【数据月份、默认清洗与固定分箱】下，总事务数为【N】，前件和后件共同出现于【nAB 条、支持度】行程；两个方向的置信度分别为【数值】，相对后件基准比例的提升度为【数值】；Kulc 为【数值】，IR 为【数值】。该规则描述关联，不证明【因果关系】，还需检查【区域、时段或数据记录机制】。

## 练习六：复现课件反例

L3 p.38 的例子：N=1000、nA=600、nB=750、nAB=400。四格计数为 400、200、350、50；A→B 置信度约 66.67%，但 B 的基准比例为 75%，lift 约 0.8889。高置信度未必表示相对基准的正关联。

保持 nA、nB、nAB 不变，新增 100,000 条既不含 A 也不含 B 的事务，观察 lift 和支持度变化，而双向置信度、Kulc 和 IR 不变。这里的空事务是相对于 A/B 而言，不是原始数据的空行或缺失值。Kulc 衡量双向重合，IR 衡量边际不平衡；不能把这些数值自动转成统计显著或因果结论。

## 当前真实案例

2025-01 默认清洗的 N=3,445,399。`费用=负值` 与 `支付=争议` 的 nA=62,320、nB=75,493、nAB=36,969，因此 n10=25,351、n01=38,524、n00=3,344,555。A→B 置信度为 59.32%，B→A 为 48.97%，lift=27.0734、Kulc=0.5415、IR=0.1306。

这些计数可在当前快照的事务表独立核对；负费用及支付争议可能涉及记录机制，规则本身不能确定欺诈或原因。比较“很高的 lift”和“两方向约一半的重合”各自在描述什么。
